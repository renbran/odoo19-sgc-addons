Connect Odoo's Social Media application to Buffer. Import Buffer
channels as social accounts, then publish immediately through the
channel queue or schedule posts for a specific date without leaving
Odoo.

The connector uses Buffer's GraphQL API with an account API key. It does
not implement OAuth, synchronization, statistics, or remote deletion.

Phase 1 supports text-only posts. Buffer requires publicly hosted media
URLs; private Odoo image and video attachments are therefore rejected
with a clear publication error instead of being uploaded or exposed.

Installation
============

Install **Social Media Base** and then **Social Media Buffer** from the
Apps menu. The only external Python package used directly by this module
is ``requests``, which is already an Odoo dependency.

No controller, OAuth callback, client ID, client secret, or web asset
requires configuration.

Configuration
=============

In Buffer, open **Settings > API** and create an API key. Do not put the
key in source code, configuration files under version control, or
client-side assets.

In Odoo, a system administrator opens **Social Media > Configuration >
Buffer Connections** and creates a connection:

- enter a recognizable name and the Buffer API key;
- optionally enter a Buffer organization ID to import only that
  organization;
- leave the organization ID empty to import every organization available
  to the key.

Save the connection and press **Import Channels**. The operation can be
repeated safely: existing channels are updated by their Buffer channel
ID rather than duplicated. Social media administrators can run the
import with a key already stored by a system administrator, but cannot
read the protected key field.

The key is stored in Odoo with access restricted to the System group.
API calls are made only by the Odoo server.

Usage
=====

After importing channels, create a Social Media post and select one or
more Buffer accounts.

- **Post now** creates the Buffer post with
  ``schedulingType: automatic`` and ``mode: addToQueue``, so Buffer
  chooses the next queue slot.
- **Schedule** creates it with ``mode: customScheduled`` and sends
  Odoo's schedule date as a UTC ISO 8601 ``dueAt`` value.

A successful call stores Buffer's post ID as the publication remote
reference and its ``externalLink``, when Buffer already provides one. In
this publishing flow, **Posted** means Buffer accepted the post; queued
and custom-scheduled posts can still be awaiting delivery by Buffer.

A typed Buffer ``MutationError`` or a response without a post ID fails
only the affected publication. HTTP throttling, GraphQL errors,
validation failures, and connection errors are retained as readable
failure reasons.

Phase 1 accepts no Odoo image or video attachments on Buffer posts. Host
media at a stable public HTTPS URL and use Buffer directly for media
posts until URL asset support is implemented.

Known issues / Roadmap
======================

- Support Buffer assets from explicitly configured, stable public media
  URLs.
- Add channel-specific scheduling validation for Instagram personal
  profiles and Facebook groups, which Buffer documents as
  notification-only channels.
- Reconcile queued and scheduled Buffer post delivery states and
  external links.
- Add optional post statistics and remote deletion through separate
  connector modules so publishing remains independent of
  synchronization.
